# 性能基准

基准程序测量真实的 Unicode 归一化、词库编译、Aho-Corasick 匹配和结果数组分配。它用于同一环境下的回归比较，不代表生产环境延迟承诺。

快速运行：

```bash
php benchmarks/worker.php 1000 100 3
```

三个参数依次是敏感词数量、输入文本 Unicode 码点数和扫描次数。程序输出一个 JSON 对象，包含：

- `compileMs`：内部词库编译时间；
- `constructionMs`：完整 `Matcher` 对象构造时间；
- `coldScanMs`：新对象第一次查找耗时；
- `warmScanP50Ms`、`warmScanP95Ms`：复用同一对象的查找耗时；
- `denseContainsP50Ms`、`denseContainsP95Ms`：密集命中时提前结束的判断耗时；
- `compiledDeltaBytes`、`processPeakBytes`：编译后内存增量和进程峰值内存；
- 无命中、稀疏命中和密集命中三种输入形态。

完整矩阵：

```bash
php benchmarks/run.php
```

完整矩阵测试 1,000、10,000、50,000、100,000 个敏感词，以及 100、1,000、10,000 个码点的文本。结果写入被 Git 忽略的 `benchmarks/results/`。可通过 `SENSITIVE_TEXT_BENCHMARK_ITERATIONS` 设置正整数迭代次数。

比较结果时应保持机器、PHP、ICU、迭代次数和输入形态一致，并比较多次运行的中位数。内存字段来自进程级测量，只适合相同环境的相对比较。

以下为结构简化及全串 Unicode 归一化调整前的历史数据，不代表当前版本性能。当前实现保留 packed 来源映射，匹配区间和结果直接使用数组，已移除旧区间对象的隔离比较基准。

当前 `contains()` 先完整验证 UTF-8，无白名单时在首个自动机输出处停止匹配。ASCII 路径可逐字符转换；Unicode 路径先执行全串归一化，再推进匹配。存在白名单时，会构建完整映射并定位白名单区间。

ASCII 快速路径可用以下命令复现。`--ascii-comparison` 在同一次进程中用同一归一化核心比较快速路径和 Unicode 回退路径，区别仅由内部基准开关控制：

```bash
php benchmarks/worker.php 1000 10000 7 --ascii-comparison
```

受控原始结果保存于 `benchmarks/baselines/20260922-ascii-comparison.json`。10,000 字符 P50 数据为：无映射归一化 1.44 ms 对 11.47 ms，带映射归一化 1.57 ms 对 11.55 ms，无命中流式判断 2.03 ms 对 12.26 ms。首字符命中为 0.0098 ms 对 0.0015 ms，此时完整 UTF-8 验证和 ASCII 路径检测占主导，快速路径没有收益；保留快速路径的依据是完整转换和无命中场景的稳定改善。Unicode 输入始终走 grapheme 和 ICU 归一化流程。

当时的来源映射隔离测试构建 10,000 个区间：区间对象为 1,590,584 字节、0.714 ms；两个 packed int lists 为 532,592 字节、0.162 ms。极端 combining marks 输入为 10,000 个码点，归一化耗时 4.83 ms，映射内存增量 1,405,824 字节。高后缀重叠测试产生 61,984 个结果，耗时 214.92 ms。这些数据用于保留历史比较背景，当前结果数组和归一化流程的开销应重新测量。
